# ZeroOne Ops

Governed OpenAI-assisted engineering workflows, operated through GitHub or
GitLab issues and pull/merge requests.

ZeroOne Ops reviews changes, collects normalized scanner findings, and prepares
bounded remediation requests. Operators control policy and recovery; validation,
review, and provider-native lifecycle evidence remain visible alongside the work.

## Start Operating

- [Getting Started](getting-started.md): choose a provider and install the CI templates.
- [Configuration](configuration.md): configure credentials, scanner inputs, and validation.
- [Workflows](workflows.md): understand policy, batches, review, and recovery.
- [Troubleshooting](troubleshooting.md): interpret failures and find the next action.
- [V1 Migration](migration-v1.md): upgrade an older installation safely.

## Detailed Reference

The [operator runbook](runbook.md) remains the canonical procedural reference.
These entry pages guide you to its relevant sections rather than maintaining a
second set of instructions. See the [review flow](review-flow-mermaid.md) and
[roadmap](roadmap.md) for current boundaries and direction.

This unversioned website follows `main` and may describe changes newer than the
latest release. Use the documentation and templates from your installed
[release tag on GitHub](https://github.com/JustinMelger/ZeroOne-ops/tags) when
you need a release-specific reference. The
[design library](https://github.com/JustinMelger/ZeroOne-ops/blob/main/docs/design/README.md)
preserves current architecture contracts and clearly marked historical records.
